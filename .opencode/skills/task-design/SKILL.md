## Purpose

Skill преобразует проверенный Requirement Review в Jira Tasks Artifact — спецификацию создания, пригодную для исполнения паблишером без дополнительных решений. Запись в Jira Skill не выполняет.

## Inputs

Обязательно: валидный Requirement Review Artifact и Scope текущей задачи. Опционально: проектные правила декомпозиции, допустимые типы задач и приоритеты из Context, сведения о существующих задачах, полученные агентом read-only.

## Procedure

1. Определи, какие подтверждённые требования требуют отдельной работы команды разработки.
2. Сгруппируй связанные требования в целостные задачи; разделяй задачи с разными целями, критериями приёмки или независимыми рисками.
3. Не дроби работу без самостоятельной ценности и проверяемого результата.
4. Для каждой задачи сформируй Summary, Description, Acceptance Criteria и Source Requirements.
5. Сохрани Traceability к требованиям и укажи зависимости (тип связи + Local ID цели).
6. Назначь Priority, только если она обоснована риском, бизнес-критичностью или Context; иначе пометь «требует внешнего решения» и оставь поле незаполненным.
7. Присвой задачам Local ID `T-<n>`, проверь дубли по существующим задачам.
8. Проставь `Ready to create: yes|no` с причиной для `no`.
9. Сформируй artifact по структуре из Output.

## Rules

- Не создавай задачу без основания в Requirement Review.
- Не добавляй Acceptance Criteria, которых нет в подтверждённых требованиях.
- Бизнес-неоднозначности самостоятельно не разрешай: неразрешённое противоречие — это Open Question, а не критерий приёмки.
- Не определяй Jira-проект, Assignee, Sprint, Fix Version и другие проектные поля самостоятельно, если они не переданы Context.
- Не смешивай в одной задаче независимые изменения; не создавай несколько задач об одном и том же.
- Только read-only Jira. Никаких create, edit, transition, comment, link, worklog.
- Спецификация не содержит Jira Key, Issue ID, статусов и отметок о создании — факт создания фиксирует паблишер.
- Формат описания задачи — plain text/Markdown по разделам спецификации; специфичного Jira-guide для описания задачи нет.

## Output

Artifact `artifacts/jira-tasks/<version>.md`: шапка из AGENTS.md §6, метаданные проекта (ключ, тип задачи, обязательные поля, допустимые типы связей), раздел проверки дублей и таблица покрытия требований, затем по каждой задаче:

- Local ID (`T-<n>`)
- `Ready to create: yes|no`
- Issue Type
- Summary
- Description
- Acceptance Criteria
- Source Requirements
- Dependencies (тип связи + Local ID цели)
- Priority или «требует внешнего решения»

В конце: список задач с `Ready to create: no` и причиной (BLOCKED / REQUIRES_HUMAN_DECISION / возможный дубль с ключом).

## Completion Criteria

- каждая задача имеет основание в Requirement Review;
- каждое значимое требование покрыто задачей либо явно отмечено как не требующее отдельной задачи;
- Summary и Description понятны без чтения истории агента;
- Acceptance Criteria не содержат придуманных бизнес-правил;
- Traceability сохранена; зависимости указаны с Local ID;
- необоснованные дубликаты отсутствуют, проверка дублей отражена;
- критические Ambiguities и Conflicts не скрыты;
- у каждой задачи есть `Ready to create`, у каждого `no` — причина;
- спецификация не содержит ключей Jira, ID и следов создания;
- artifact готов к передаче `jira-publisher` без дополнительных решений.
